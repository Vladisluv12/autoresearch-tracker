# claudes-tracker-harness

Трекер задач и правила работы для нескольких агентов Claude Code (или других агентов), которые параллельно работают над одним репозиторием с разных машин. Его сделали в начале хакатона для команды из трёх агентов. Здесь оставлен только харнесс координации, без кода решения и условия задачи.

[Протокол координации](docs/COORDINATION.md) · [Роли команды](docs/TEAM.md) · [Стартовые промпты](docs/START_PROMPTS.md) · [Бриф задачи (шаблон)](docs/BRIEF.md).

Несколько Claude или других агентов могут работать с разных машин. Код живёт в отдельных ветках, а общий трекер — в ветке `coordination` этого же репозитория. Для координации нужны **Git и Python 3.10+**, без сторонних Python-пакетов и отдельного сервера.

## Подключить машину

У каждого рабочего агента — свой клон, уникальный `agent-id` и обычный Git-доступ на запись в этот репозиторий. Учётные данные настраиваются на каждой машине; секреты в репозиторий не кладём. Одного GitHub-аккаунта достаточно, если агенты имеют разные `agent-id`.

```sh
git clone https://github.com/dub-otrezkov/claudes-tracker-harness.git
cd claudes-tracker-harness
python3 scripts/coord.py identity josh --role algorithms
python3 scripts/coord.py whoami
python3 scripts/coord.py list
```

Пример выше — для `josh`. Выберите свой ID и роль из [TEAM.md](docs/TEAM.md), готовые инструкции для участников — в [START_PROMPTS.md](docs/START_PROMPTS.md). Идентичность хранится локально в Git-конфигурации клона; переменные `COORD_AGENT` и `COORD_ROLE` позволяют её переопределить. Если на одной машине несколько агентов, используйте отдельный клон и уникальный ID для каждого.

Перед работой агент читает [AGENTS.md](AGENTS.md). Для Claude входная точка — [CLAUDE.md](CLAUDE.md).

## Взять задачу

```sh
python3 scripts/coord.py create "Краткое название" \
  --description "Что нужно сделать" \
  --acceptance "Проверяемый результат" \
  --scope src/example
python3 scripts/coord.py claim T001
git fetch origin
git switch -c agent/josh/T001-short-title origin/main
```

Используйте ID, который вернула команда `create`, и свой `agent-id`. `--scope` можно повторять: это конкретные пути от корня репозитория; `*` резервирует весь репозиторий. Другие шаблоны не поддерживаются. Зависимости задаются повторяемым `--depends-on T001`.

`claim` разрешает работу, только если зависимости завершены и область не занята другой активной задачей. Начинайте менять файлы **после успешного `claim`**. Пример дальнейшей работы:

```sh
python3 scripts/coord.py heartbeat T001 --note "Короткий прогресс"
# Правки, проверки, коммит и push своей ветки, затем PR.
python3 scripts/coord.py handoff T001 \
  --summary "Изменения: …; проверки: …; риски: …; ветка: agent/josh/T001-short-title" \
  --pr https://github.com/dub-otrezkov/claudes-tracker-harness/pull/123
```

Ссылку на PR замените настоящей. Отправляйте heartbeat примерно каждые 10 минут. При возобновлении работы и перед коммитом или push сначала проверяйте владение успешным `heartbeat`.

Полный порядок работы, блокировки и восстановление — в [протоколе координации](docs/COORDINATION.md). [Общая доска на GitHub](https://github.com/dub-otrezkov/claudes-tracker-harness/blob/coordination/BOARD.md) отображает последнее опубликованное состояние; актуальное состояние можно получить через `list` и `show`.

## Подготовка трекера

Общая ветка `coordination` уже создана. Команда `python3 scripts/coord.py init` создаёт её при отсутствии; повторный запуск сохраняет существующие задачи.

Ветка `coordination` должна допускать прямые Git-push от участников. Не распространяйте на неё требования `main` об обязательных PR, проверках и подписанных коммитах. Трекер добавляет последовательные коммиты с проверкой ожидаемого предыдущего коммита; разрешать переписывание истории для него не требуется. Не редактируйте его ветку вручную.

## Проверить трекер

```sh
python3 -m unittest discover -s tests -v
```

Интеграционные тесты создают временный локальный bare-репозиторий и два независимых клона. Они проверяют конкурентные обновления, захват задач и областей, зависимости и передачу просроченной задачи. Доступ к GitHub для тестов не нужен. GitHub Actions запускает эти проверки на Python 3.10 и 3.13.
